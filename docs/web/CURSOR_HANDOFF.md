## Прямое взаимодействие с Сергеем

Если чат Star Typing / родительский бот недоступен (лимиты, обрыв), **Сергей пишет прямо в этот чат Cursor**. Для обычной работы **не нужно** возвращаться через родителя. Пользователю достаточно текущего плана, этих документов и собственного чата Cursor.

Не приписывай родительскому боту полномочий поверх владельца. Сергей — источник направления.

Схема работы:

1. Согласованный план (эта очередь S0–S7).
2. Один ограниченный этап.
3. Реализация с сохранением удачных web-решений (React 19, TS, Vite, FastAPI, PWA, радио, скины, ContinueHub, Орион).
4. Точечные regression tests при отладке.
5. Общие проверки конечного HEAD: frontend + backend + e2e + Docker. Не skip / xfail.
6. Отдельная небольшая ветка и штатный PR с честной зависимостью (не складывать в PR17/18).
7. Короткий отчёт: что сделано / не сделано, реальные тесты, SHA, PR/Actions ссылки, риски/блокеры.
8. Следующий **уже утверждённый** этап.

Веб-план **уже целиком разрешён** Сергеем (10:12, доп. 10:14). **Не проси «продолжай»** после каждого зелёного этапа, если нет новых существенных решений.

«По плану» = существующая очередь S0→S7, не новые идеи и не улучшения вне scope.

На вопрос «что там?» — фактический этап, результат или блокер. Не пустое обещание. Не называй зелёным то, что ещё **running**. Не путай локальные тесты с GitHub Actions.

Документацию этого комплекта **обновляй** по выполненным изменениям (PROGRESS, статус этапа).

Desktop 3.8.3 — референс **поведения**. Удачные web-решения сохранять.

«Продолжай» / «давай» на текущую работу **не** разрешает сами по себе merge, release, деплой, покупки, удаление данных. **Merge только** по явному указанию Сергея с конкретным scope и после **зелёных latest checks** на GitHub.

Платный перерасход никогда не включать автоматически. Модель не менять самовольно.

Если Сергей прямо отменяет или останавливает работу — **сразу остановиться**, сохранить состояние (commit/push checkpoint), **не возобновлять** без его указания.

Десктопные Qoder / Лаборатория / widget **не** часть текущей web-очереди.

## Возобновление (коротко)

```text
1. git fetch; сверить remote SHA master и текущей рабочей ветки.
2. Не rebase / amend / force-push опубликованного.
3. PROGRESS.md → какой этап in progress / HEAD / PR.
4. BLOCKERS.md → нет ли блокера.
5. Один этап из WEB_PARITY_STAGES.md. Не начинать следующий, пока текущий не зелёный на GitHub CI + Docker.
6. Ветка cursor/<этап>-acfe от актуального master (S0–S3 и PR21/22 уже влиты).
7. ManagePullRequest: base_branch = master; в теле — ссылки на контекст.
   GitHub — source of truth: Origin stack_on недоступен; не обходить через gh pr create.
8. Нет merge / deploy / release, пока Сергей не скажет явно.
```

Проверки этапа (локально, затем GitHub):

```bash
export CI=1 TRANSLATE_OFFLINE=1
cd backend && python -m pytest -q
cd ../frontend && npm test && npm run build && npx playwright test
# Docker: см. .github/workflows/docker-smoke.yml (start.sh --no-open)
# Локальный старт пользователю: ярлык / start-star-typing-web.bat /rebuild — без down -v
```
